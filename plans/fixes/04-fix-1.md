# Fix 04-1: state model for `stunde.md`, revision page, setup and docs details

Plan 04 is implemented on this branch, but its procedure reads state from `## Verlauf` and from
which files exist, and writes `Schritt: Tafelbild` before the OneNote gate. This fix replaces that
with the state model below. It is binding word for word and overrides any other wording in
`orchestration.md`, `lesson-folder.md`, and the entry points. Read `SPEC.md` (sections 6, 9, 11.3),
all files in `plugin/skills/`, and `plugin/agents/` first. Every mechanical requirement gets its
check or test first.

## State model

`stunde.md` holds the whole state in two sections. The procedure reads state only from them, never
from `## Verlauf` (a log for the teacher, written but never read) and never from which files exist
or which is newest.

```markdown
## Stand
Schritt: <Planung | Prüfpunkt | Tafelbild | Fertig | Abgebrochen>
Runde: <n> von 3
Planversion: <N oder „keine“>
Freigegebener Plan: <Dateiname oder „keiner“>
Tafelbildversion: <M oder „keine“>
Prüfbericht: <Dateiname oder „keiner“>
Rückmeldung: <Dateiname oder „keine“>

## OneNote
Abschnitt: <Name oder „offen“>
Seitentitel: <Titel oder „offen“>
Seiten-ID: <ID oder „keine“>
Alte Seite: <Titel oder „keine“>
```

- `Runde` is the round of the recorded draft in the current loop, `0` when the current loop has no
  draft yet. The current loop is the planning loop while `Schritt` is `Planung`, the board loop
  while it is `Tafelbild`.
- The recorded draft is `planung_v<Planversion>.md` in the planning loop and
  `tafelbild_v<Tafelbildversion>.json` in the board loop. Its review is `review_v<N>.md` or
  `tafelbild-review_v<M>.md` with the same number.
- `Prüfbericht` is the last review whose verdict was read. `Rückmeldung` is the teacher input that
  started the current loop (`rueckmeldung_vN.md` or `tafelbild-rueckmeldung_vM.md`), an input of
  every round of that loop, `keine` when the loop started without teacher input.
- Version numbers never restart: a draft gets the number after the recorded `Planversion` or
  `Tafelbildversion` (1 when it is `keine`). Teacher input gets the number of the draft it leads
  to: `rueckmeldung_v<Planversion + 1>.md`, `tafelbild-rueckmeldung_v<Tafelbildversion + 1>.md`.

Writes (each one a single edit of `stunde.md`, made only after the step completed):

| Event | Written together |
|---|---|
| Lesson created | all lines above; `Schritt: Planung`, `Runde: 0`, the rest `keine`/`keiner`/`offen` |
| Author returned `DONE` in round n | `Runde: n`, `Planversion` or `Tafelbildversion`; in board round 1 also `Seiten-ID` |
| Planning verdict `APPROVED` read | `Prüfbericht`, `Freigegebener Plan`, `Schritt: Prüfpunkt` |
| Board verdict `APPROVED` read | `Prüfbericht`, `Schritt: Fertig` |
| Verdict `REVISE` read | `Prüfbericht` only |
| Teacher feedback at the checkpoint, or `Ich gebe Hinweise` in the planning loop | the saved file as `Rückmeldung`, `Schritt: Planung`, `Runde: 0` |
| `Ich gebe Hinweise` in the board loop | the saved file as `Rückmeldung`, `Runde: 0` |
| `So übernehmen` | the accepted Mängel under `## Übernommene Mängel`, then as after `APPROVED`; in the planning loop the OneNote gate follows directly, because escalation and checkpoint are one question (`SPEC.md` 6.3) |
| OneNote gate passed | `Schritt: Tafelbild`, `Runde: 0`, `Rückmeldung: keine`, `Abschnitt`, `Seitentitel` |
| `Abbrechen` | `Schritt: Abgebrochen` |

Resume (and the next step after every write), decided from these lines only:

1. `Schritt: Prüfpunkt`: ask the checkpoint question again, or go to the OneNote gate when
   `plan_checkpoint` is `false`.
2. `Schritt` `Planung` or `Tafelbild` with `Runde: 0`: the author of round 1 runs.
3. `Prüfbericht` is not the review of the recorded draft: the reviewer of round `Runde` runs.
4. `Prüfbericht` is the review of the recorded draft (its verdict is read again from line 1):
   `REVISE` with `Runde` below 3, the author of round `Runde + 1` runs; `REVISE` with `Runde: 3`,
   the escalation question is asked.
5. A resume never starts a fresh cap.
6. A board loop needs `Schritt: Tafelbild`, which exists only after the gate passed, so a stopped
   gate leaves `Prüfpunkt` and a resume runs the gate again. A resumed board loop resolves
   `section_id` from the recorded `Abschnitt` name; if that section no longer exists, it stops with
   a German message instead of choosing another section. It keeps `Seitentitel` and `Seiten-ID`.
7. A versioned file that `## Stand` does not record (as draft, `Prüfbericht`, `Rückmeldung`, or
   `Freigegebener Plan`) comes from an interrupted agent run: it is never an input, and the agent's
   next run writes the same path again. This is the only case in which a versioned file is
   overwritten.

## Phase 1: `lesson-folder.md` and `orchestration.md`

Files: `plugin/skills/lesson-conventions/lesson-folder.md`,
`plugin/skills/lesson-conventions/orchestration.md`, `checks/rules/orchestration.ts`, and its test.

Acceptance criteria:

1. `lesson-folder.md` shows `## Stand` and `## OneNote` exactly as above in the `stunde.md` format
   and states the meaning of each line and the overwrite rule of resume step 7.
2. `orchestration.md` follows the state model: the write table, the resume steps, and nothing that
   reads `## Verlauf`, checks which files exist to decide a step, or writes `Schritt: Tafelbild`
   before the gate passed.
3. `Seiten-ID` is written only from a board author's `DONE` line. After a protocol error of the
   board author in round 1, the re-run gets the same assignment, and the finish message tells the
   teacher that an empty page with the title may exist from the failed run.
4. Rule `orchestration` checks that `lesson-folder.md` contains the lines `Prüfbericht:`,
   `Rückmeldung:`, and `Alte Seite:`, with a failing test that asserts rule name and file.
5. `npm run verify` passes.

## Phase 2: entry points, setup, and docs

Files: `plugin/skills/stunde-planen/SKILL.md`, `plugin/skills/stunde-ueberarbeiten/SKILL.md`,
`plugin/skills/einrichten/SKILL.md`, `README.md`, `CHANGELOG.md`.

Acceptance criteria:

1. `stunde-planen` creates `stunde.md` with every line of the state model as in the table.
2. `stunde-ueberarbeiten` resumes only by the resume steps, never from `## Verlauf`.
3. Revising a finished or aborted lesson is one write: the teacher's changes saved as the next
   `rueckmeldung_vN.md` and recorded as `Rückmeldung`, `Schritt: Planung`, `Runde: 0`,
   `Freigegebener Plan: keiner`, `Alte Seite` set to the current `Seitentitel` (or kept when it is
   already set and no new page exists yet), `Seitentitel: offen`, `Seiten-ID: keine`. The OneNote
   gate then derives the new title from `Alte Seite`: the old title followed by ` (überarbeitet)`,
   or ` (überarbeitet 2)`, ` (überarbeitet 3)` and so on when that title exists in the section.
   The finish message names `Alte Seite` as the page to delete. A revision never reads or writes
   the old page.
4. `einrichten`: when the Ansicht in `onenote.md` already holds numbers, ask one quoted German
   question whether to measure again, instead of the projection question; when the allow rules
   are not written (declined, invalid JSON, or an unexpected shape), the final summary lists them
   as missing.
5. `README.md` and `CHANGELOG.md` describe the cap as at most three rounds (for example
   `höchstens drei Runden`), never as three revisions.
6. No other file changes. `npm run verify` passes, and `npm run verify:release` fails with exactly
   one finding: the server is not vendored.
