# Fix 02-1: review format, conventions scope, German examples and templates

Plan 02 (`plans/02-conventions-and-templates.md`) is implemented on this branch. This fix changes
only what is listed below. Read `SPEC.md`, plan 02, and the current files first; their rules still
apply. Every mechanical requirement gets its check or test first.

## Phase 1: `lesson-conventions/SKILL.md`

Files: `plugin/skills/lesson-conventions/SKILL.md`, `checks/rules/conventions.ts`, and its test.

Acceptance criteria:

1. **Review format:** after line 1, exactly these headings in this order: `## Muss-Mängel`,
   `## Soll-Hinweise`, `## Nachrechnung`, `## Frühere Muss-Mängel`. `## Muss-Mängel` lists only the
   defects that are open now, numbered. `## Frühere Muss-Mängel` has one line per Muss-Mangel of
   the previous review, in the form `- <Mangel>: behoben` or `- <Mangel>: offen`; an open one is
   also listed under `## Muss-Mängel`. When the assignment lists no previous review, the section
   holds `- keine`. Every other rule of the review format stays as it is, and it still applies to
   board reviews too.
2. **Working folder:** the rules "write only the `output` named in the assignment", "never change
   the teacher's own files", and "use only the paths the assignment lists" are stated as rules for
   agents. The section adds that the entry points follow `lesson-folder.md` and `orchestration.md`
   instead, and that `einrichten` changes a teacher's file only after showing the change and
   getting a yes (`SPEC.md` section 9).
3. **Glossary:** the meaning of `Stundenthema` is "the topic of the lesson: the title of the plan
   and the first line of the Tafelbild". The OneNote page title is the assignment's `page_title`,
   not the Stundenthema.
4. Rule `conventions` also requires the heading `## Frühere Muss-Mängel`, with a failing test that
   asserts rule name and file.

## Phase 2: examples, templates, and the examples rule

Files: `plugin/skills/lesson-conventions/examples/plan.md`,
`plugin/skills/lesson-conventions/examples/board.json`,
`plugin/skills/lesson-conventions/examples/NOTES.md`, `plugin/templates/CLAUDE.md`, any other
template that addresses the teacher, `checks/rules/examples.ts`, and its test.

Acceptance criteria:

1. `examples/plan.md` and `examples/board.json` describe the Zähler unambiguously, for example
   `Zähler: wie viele dieser Teile gemeint sind`, next to `Nenner: in wie viele gleich große Teile
   das Ganze geteilt ist` (or wording of the same precision). The plan's `## Tafelbild (Inhalt)`
   and `board.json` stay in sync.
2. The sentence in `examples/plan.md` that starts `Die Stunde legt die Grundvorstellung` is a
   complete, correct German sentence.
3. `examples/NOTES.md` is recomputed for the changed texts: every character count, line count,
   height estimate, and `x + width` matches `board.json` and the formula in `board.md`.
4. Every German text in `plugin/templates/` addresses the teacher with "du", never "Sie", matching
   the checkpoint question of `SPEC.md` section 6.3. Reviews are called `Prüfberichte`, never
   `Prüfungen`.
5. `templates/CLAUDE.md` describes `/unterricht:stunde-ueberarbeiten` as continuing an interrupted
   lesson or revising a finished one (`SPEC.md` section 5.3).
6. Rule `examples` checks the paragraph's own `font_size` also when the paragraph has `segments`,
   with a failing test that asserts rule name and file.
7. No other file changes. `npm run verify` passes.
