Plan 03 (`plans/03-agents.md`) is implemented on this branch. This fix changes only what is listed
below. Read `SPEC.md`, plan 03 (its board-author criteria are binding, word for word), the agent

test first.

## Phase 1: board author and the inputs of both reviewers

Files: `plugin/agents/board-author.md`, `plugin/agents/board-reviewer.md`,
`plugin/agents/plan-reviewer.md`.

Acceptance criteria:

1. `board-author` self-check (today "change it until every check holds"): a single correction pass
   that keeps every item of `## Tafelbild (Inhalt)` verbatim, in plan order, with nothing added. A
   check that still fails is not looped on: the author goes on and writes the page, the board
   reviewer reports it, and the board loop's cap and escalation decide.
2. `board-author` `create_page` recovery, after every `list_pages` check: a new page is one titled
   exactly `page_title` whose ID was not noted before the first `create_page`. Exactly one new
   page: use it. More than one new page: `FAILED`. No new page after the first call: the second
   call. No new page after the second call: `FAILED`. Still at most two `create_page` calls per
   round.
3. Every `FAILED` reason of the `create_page` recovery is German, names the section and the title,
   and asks the teacher to delete empty pages with that title in that section before continuing
   with `/unterricht:stunde-ueberarbeiten`.
4. `board-author` and `board-reviewer` decide whether the Ansicht is configured only after reading
   `board.md` (the rule is there); reading `onenote.md` earlier stays allowed.
5. `plan-reviewer`: the plan it judges is the `planung_vN.md` whose N matches the `review_vN.md`
   named in `output`. A previous plan in `inputs` is context only. The Inputs section lists the
   previous plan as an optional input.
6. No other file changes. `npm run verify` passes, and the `agents` and `agent-bodies` rules report
   nothing.
